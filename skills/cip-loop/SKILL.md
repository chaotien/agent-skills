# CIP Loop（持續改進迴圈）

## 這個 skill 在解決什麼

系統真正變好，多半不是靠一開始想得多周全，而是靠每天用、每天發現一點不順，然後一點一點改掉。問題是這些發現很容易散掉：當下想到、沒記、隔天就忘；或者記在聊天裡，下一個接手的人和 agent 都看不到。

CIP.md 就是接住這些發現的地方。它只有一條規則最重要：**想到就記一行，先不判斷大小**。挑哪一項做、要不要做，是之後的事。

兩個來源都往同一份檔寫：

- **人**：用了、測了，覺得哪裡不順
- **agent**：實作、測試時順手發現的問題

它在開發流裡的位置：`survey-mode` → `rolling-plan` → `repo-init-adopt` → **`cip-loop`**，而且這一步會一直轉下去。

## CIP.md 規則

```markdown
# CIP

| # | 項目 | 來源 | 狀態 | 備註 |
|---|---|---|---|---|
| 1 | 匯出報表時欄位順序亂掉 | 人 | done | |
| 2 | 測試時發現空資料會讓 parser 崩潰 | agent | doing | |
| 3 | 想要一鍵同步到筆記軟體 | 人 | open | |
| 4 | 自動分類規則 | 人 | dropped | 用了兩週發現手動比較快 |
```

- **一項一行**：一句話描述、來源（人／agent）、狀態（open / doing / done / dropped）。
- **用名稱，不帶版號**，例如「CIP Report」，不要寫「CIP Report v3」。
- **做完改狀態，不刪列。** 整份清單就是累計帳，回頭看得出這個系統是怎麼長大的。
- **放棄的標 dropped，寫一句理由。** 理由比結論更值得留下來。
- **小改進只留在 CIP.md，不碰 PLAN.md。**
- 少數需要背景或討論的大項目，可以另開 `docs/cip/<名稱>.md`，從這一行連過去。預設只用一份檔。

## 步驟

1. **記**：把發現寫成一行。先不判斷大小、不判斷要不要做。
2. **挑**：開工時從 open 裡挑一項。優先挑**當前 phase 完成條件需要的**；其次挑人提的、卡住日常使用的。
3. **做**：實作，然後**實跑一次**確認真的有效。做的過程中又發現的問題，照樣記成新的一行——這就是迴圈。
4. **收**：改狀態。若這項動到了方向、phase 順序或完成條件，在 PLAN.md 決策紀錄記一筆，並連回這一行 CIP。

## 紅線

- **不在記的當下爭論要不要做。** 爭論會讓人下次懶得記。先記，挑的時候再判斷。
- **不刪列。** 包括做完的和放棄的。
- **agent 不自己把大項目標成 done。** 動到使用方式或方向的項目，由人確認後才收。

## 完成檢查（每輪收工）

- [ ] 這輪的發現都記進 CIP.md
- [ ] 做完的項目已改狀態，放棄的有寫理由
- [ ] 動到方向的已回寫 PLAN.md 決策紀錄，並連回這條 CIP
