# Swiss Slide Style（雙色語意版）

給技術團隊向上報告用的投影片規格：一頁一件事、字要大、一個顏色只代表一個意思。

分兩層：**基礎層**所有簡報都要遵守；**語意層**是全域固定的顏色與線型對照，任何 project 都不可改寫它的意思。專案需要額外語意時，只能寫進該專案附錄，且不得與語意層衝突。

---

## 1. 基礎層

### 1.1 調性
- Swiss 極簡：白底、近黑字、大量留白
- **一頁一件事**；副標用一句話講完結論
- 不用裝飾底線、色條、漸層、陰影；圓角最多小圓角（約 8px / 0.1in）
- 每頁至少一個視覺元素（流程格、比較表、2×2、Gantt、stack 圖、大數字），不做純文字頁
- 敘事順序：先分析（現況、痛點、數據），再給方案
- 先用留白換字級：要放大字時，先縮邊界，不要把字擠在一起

### 1.2 畫布與版面
- 16:9。HTML 為 1920×1080；PPTX 為 13.33×7.5in
- 邊界：左右 80px（0.55in），上 48–56px，頁尾貼底 40px
- 大標題、副標**置中**
- 內容放在淺灰區塊卡片裡；卡片內的小卡用白底、不加外框

### 1.3 中性色
| 用途 | Hex |
|---|---|
| 背景 | `#FFFFFF` |
| 主文字 | `#1A1A1A` |
| 次要文字 | `#5C5C5C` |
| 頁尾、註記 | `#8A8A8A` |
| 區塊卡片底 | `#F2F2F2` |
| 格線、分隔線 | `#D9D9D9` |
| 非工作日底 | `#E6E6E6`（或斜線） |

### 1.4 字型
- PPTX：中文用 Microsoft JhengHei（微軟正黑體）；英文標題、數字、標籤用 Arial（粗體）
- HTML / 網頁簡報：Noto Sans TC，備援 Arial、Microsoft JhengHei

### 1.5 字級（px 為 1920 畫布，pt 為 PPTX；1pt ≈ 2px）
| 元素 | 一般版 | 長官版（視力較吃力的長官、大會議室投影） |
|---|---|---|
| 頁面大標 | 26–30pt / 52–60px，粗體 | 同左 |
| 副標 | 14–16pt / 28–32px，灰 | 16–17pt / 32–34px |
| 卡片標題 | 13–15pt，粗體 | 15pt / 30px，粗體 |
| 條列內文 | 11–12pt | 13pt / 26px（內容多時降到 12pt / 24px） |
| 流程格標題 | 11–12pt，粗體 | 12.5pt / 25px |
| 流程標籤、說明 | 10pt | 11pt / 22px |
| Gantt 工作項名稱 | 11pt，粗體 | 13pt / 26px |
| Gantt 說明句 | 10pt，灰 | 11.5pt / 23px |
| Gantt bar 天數 | 9.5pt，粗體 | 10.5pt / 21px |
| 頁尾 | 9pt，灰 | 11pt / 22px |
| 最小字 | ≥ 9.5pt | ≥ 11pt / 22px |

長官版原則：非標題字比一般版明顯放大（目標接近兩倍可讀性）；放不下就拆頁，不縮字。

### 1.6 標題與語言
- 標題、副標用**英文**；內文用中文，技術名詞保留英文
- 標題格式：`<Project>｜<Topic>`，例如 `Project 101｜03 Why X is hard`、`Backup｜GPU Stack`
- 區塊標籤用英文：Pain Points、Value & Requirement、Delivered、Follow-ups & Schedule、RD / Product
- 外部合作夥伴：全英文
- 用詞全份統一（同一件事一律用同一個術語，不混用中文俗稱與英文名）
- 人名放 owner 欄或灰色小字署名，不搶主訊息

### 1.7 頁尾
一行灰字貼底：`Draft vN · YYYY-MM-DD · 計日方式 · 圖例說明`。版本號只放頁尾，不放檔名。

## 2. 語意層（全域固定，所有 project 一致）

### 2.1 強調色：紅加藍雙色
| 顏色 | Hex | 唯一意思 |
|---|---|---|
| 紅 | `#C00000` | **要注意的事**：痛點、缺口、風險、待解、時間壓力（今天、deadline） |
| 藍 | `#1912F7` | **解法與成果**：解掉紅色項目的動作、已達標、已上線、正面數字、里程碑 |
| 近黑 | `#1A1A1A` | 中性：主文、現行不用動、一般工作項 |

延伸色（只用來表示「同一件事的區間或保守值」，不帶新意思）：
| 用途 | Hex |
|---|---|
| 紅色項目延長段 | `#E6B3B3` |
| 藍色項目延長段／保守情境 | `#9A98FF`（小字用深一階 `#7B78F0`） |
| 黑色項目延長段 | `#BDBDBD` |
| 深底上的藍字 | `#9A98FF` |
| 深底上的紅字 | `#FF6B6B` |

規則：
- 整份簡報每個顏色只有上表的意思。拿不準時用近黑
- 第一頁出現的紅色問題，後面的頁面應該有對應的藍色解法或里程碑，形成「紅 → 藍」的對照
- 不准再加第三個強調色。專案確實需要時（例如琥珀色 `#E8A33D`＝其他專案佔用的人力），寫在該專案附錄並在頁面圖例說明

### 2.2 線型與填色（和顏色正交：顏色說「是什麼」，線型說「狀態」）
| 線型 | 唯一意思 |
|---|---|
| 實心填色 | 已完成 / 已存在 |
| 實線空心框 | 進行中 / 現有但需處理 |
| 虛線框 | 還沒有 / 待做 / 待定 |

常見組合：
- 黑實線框＝現行、不用動
- 紅實線框＝現有但靠人工（問題）
- 紅虛線框＝還沒有、要新加（缺口）
- 藍實心＝已完成、已上線
- 藍空心框＝解法進行中
- 黑虛線框＝待定

### 2.3 其他固定圖形
- 小紅色方塊：只當段落錨點使用，不帶語意
- 疊起來的框（錯開 6px、12px）＝「多張／多次」，例如 1 次掃描 → 多張取樣圖 → 多次人工複查
- 箭頭：流程方向；虛線箭頭＝呼叫或依賴（calls · API），實線箭頭＝流程先後

## 3. Gantt
- 左欄：編號＋名稱（粗體）＋一句「為什麼需要這些天」
- 右欄：週為單位，週標題用週碼（例如 W45、W46，或團隊慣用的 work-week 編碼），下排日期數字，日寬固定
- 標題寫總長：`Schedule — 2 Weeks (7 Working Days)`；副標列 Day 1、休假日、里程碑日期
- 天數寫 `D`：`1D`、`0.5–1D`、`2–3D`
- 每根 bar 依**下限**首尾相接；淺色延長段可以蓋到下一項
- 最快與保守兩種情境疊在同一列：深色＝最短，淺色＝可能延長或保守
- bar 顏色依語意層：一般工作項黑、解掉紅色問題的動作藍、風險中的項目紅
- 非工作日（請假、颱風假、國定假日）整欄灰底或斜線，第一列寫原因；預估假日在頁尾註明
- 今天：紅色細虛線直線
- 里程碑：藍色線段畫在對應工作項正下方，起訖對齊 bar；里程碑一＝先 deliver 的部分，里程碑二＝全部上線看得到。圖例不另列「里程碑」
- 里程碑只寫已確定的價值，沒量化前不寫效益數字
- 給老闆的 Gantt：工作項拆得越細越好，讓工作量看得見

---

## 4. 常用頁型
- **現況與需求頁**：上半部是現行流程（一排流程格加箭頭，字多的格子給寬一點）；下半部兩張卡，左 Pain Points，右 Value & Requirement。Value 一行放最上面當標題，細線分隔後接 Requirement 條列。已決議事項用「已決議：」開頭，和待辦需求分開
- **大數字**：藍色粗體，數字和單位同一行（例如 `15 tools`）
- **比較頁**：舊方法 vs 新方法比較表，或 2×2 優缺點矩陣；本方案欄可用淺藍底標出
- **兩方案對比（Head-to-Head）**：大標寫兩邊方案名稱，副標寫這次對比的 purpose，核心是一張關鍵指標比較表
- **收尾頁**：可以用深色底放一句結語，這是唯一允許非白底的頁面

---

## 5. 用字
1. **動詞**：bar 名稱寫「做完會怎樣」，不寫「我們怎麼做」
2. **三句**：做什麼／為什麼要這些天（瓶頸）／做完看得到什麼
3. **輪廓**：技術點到骨架即可，用老闆熟悉的比喻（例：資料結構像廠房預留管線和地，現在不留之後要敲牆）
4. **預答**：老闆會問的先寫進頁面或講稿
- 不用「卡在」（會被讀成走投無路）
- 不用防衛句型（「這是常態不是慢」），改成「事實＋我們怎麼做」
- 推估或示意的數字，註腳一定標「估計」或「示意」
- 外部 benchmark 或數據要查證並註明來源

---

## 6. 講稿
- 每頁附 speaker notes：主訊息一句、補充兩三點、預備答案（例如「為什麼放 A 系統不放 B 系統」）
- 需要時另附 30 秒與 1–2 分鐘的口頭版本

---

## 7. 製作與 QA
- 輸出格式：使用者沒指定格式時，用環境提供的簡報工具；指定 .pptx 時用 pptxgenjs（或同等程式化工具）
- 開工前先確認：觀眾是誰（長官版、一般版、外部）→ 決定字級表與語言
- QA：逐頁轉圖檢查（PPTX：LibreOffice → PDF → pdftoppm；HTML：截圖），確認沒有文字溢出、最小字合規、顏色語意沒有用錯
- 自檢清單：
  - [ ] 每頁只講一件事，副標就是結論
  - [ ] 紅色只用在問題、缺口、時間壓力；藍色只用在解法與成果
  - [ ] 實線、空心、虛線的狀態意思正確
  - [ ] 長官版字級達標
  - [ ] 估計值有標註
  - [ ] 頁尾有版本與日期

### HTML 匯出 PPT 的注意事項
| 不要 | 改用 |
|---|---|
| 重複漸層畫斜線或格線 | 斜線用小 SVG 圖；格線用 2px 實心色塊 |
| 多層陰影做疊框 | 三個真的方框，錯開 6px、12px |
| 空白 div 撐位置 | 占位格也給背景色，不然匯出會被吃掉 |
